## Одно объяснение — одна тема

Если понятие уже описано в `content/lessons.json`, дополняй **существующую тему**. Повторные вопросы добавляй как задачи для закрепления. Не создавай вторую основную тему с тем же механизмом.

## Единый источник данных

- `content/lessons.json` — основная теория RU/EN и принадлежность вопросов к темам.
- `content/questions.json` — вопросы RU/EN, ответы и исходные фрагменты.
- `content/glossary.json` — технические определения в двух языках.
- `labs/dotnet/*.cs` — действительно запускаемые C#-примеры.
- `site/assets/` — веб-интерфейс (никаких приватных данных).

Не редактируй сгенерированные Markdown-файлы напрямую: они пересоздаются командой:

```bash
python3 scripts/build_site.py
python3 scripts/check_links.py
python3 scripts/check_site.py
node --check site/assets/app.js
```

Для новых языков и платформ добавляй отдельные разделы и одну основную тему на уникальный механизм. Используй постоянные идентификаторы вопросов и ссылки на примеры для закрепления.

**Важно:** личные ответы, оценки и секреты в репозиторий не добавляются.
## Добавление из ChatGPT

[Как добавлять новые темы прямо из чата](docs/chat-authoring.md). Новые темы и вопросы автоматически появляются в навигации после обновления исходных JSON и запуска генератора. Не меняй `site/data` вручную.

Для других технологий добавь `track` (например, `go`, `kafka`) в новую тему. ID вопроса остаётся глобальным; `kind: "review"` — вопрос для проверки, `kind: "reinforcement"` — закрепление. Исполняемые примеры и команды хранятся отдельно, а не смешиваются с объяснением.

## Категории

Новые технологии регистрируются в [`content/catalog.json`](content/catalog.json). После добавления материала генератор автоматически обновляет README, каталог RU/EN и Pages. [Структура репозитория](docs/repository-layout.md).

## Обучение и карточки

Новые углублённые темы записывай в content/units.json, не в site/data и не в сгенерированные Markdown. Один механизм — один учебный раздел, вопросы — только закрепление. Запускай python3 scripts/build_units.py и python3 scripts/build_site.py, затем обе проверки с --check и node --test tests/spaced-repetition.test.mjs. Расписание пользователя остаётся локальным, без публикации в GitHub.
