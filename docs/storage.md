# Хранение данных и SQLite

[Русский](storage.md) · [English](storage.en.md)

[Главная](../README.md) · [Структура](repository-layout.md)

Для публичного учебника **SQLite сейчас не нужен**. Версионирование Git и `content/*.json` уже дают эталонные материалы, постоянные ID и историю изменений; `topics/` и `questions/` генерируются в Markdown, а примеры хранятся отдельно в `labs/`.

GitHub Pages — статический хостинг. Размещение SQLite-файла рядом с Pages не создаст безопасную запись результатов пользователей. Прогресс в браузере хранится в `localStorage` только на конкретном устройстве; личные оценки и ответы — отдельно в приватной Google Таблице.

**SQLite может пригодиться позже**, если добавим сервер с авторизацией для синхронизации прогресса между устройствами, истории попыток и статистики. Для более крупной многопользовательской системы можно рассмотреть PostgreSQL. Сам SQLite при этом стоит изучать отдельно как тему SQL и лабораторию.
