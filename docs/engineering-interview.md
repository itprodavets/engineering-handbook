## Принцип

Техническая подготовка — не запоминание коротких ответов. На каждом механизме нужно последовательно пройти пять проверок. Самооценка не доказывает компетентность: уровень подтверждается работой с неизвестным кодом, реальным IL, показателями и инженерными решениями.

| Уровень | Что демонстрируешь | Проверка |
|---|---|---|
| **Recall** | Точное определение и ограничения | 30–60 секунд без подсказок |
| **Explain** | Последовательность C# → Roslyn → IL/JIT → CLR → ОС | Объяснение 2–3 минуты со схемой |
| **Predict** | Поведение нового фрагмента C# | Предсказание до выполнения, затем воспроизводимый тест |
| **Diagnose** | Причину ошибки или деградации | Гипотезы, counters/traces/stack evidence |
| **Design** | Решение и компромиссы для production | Контроль ресурсов, альтернативы, границы применимости |

## Эталонный модуль: Async/Await

Проходи разделы [I/O-bound](../topics/dotnet/units/io-vs-cpu-bound.md) → [awaiter](../topics/dotnet/units/awaiter-completion-path.md) → [async state machine](../topics/dotnet/units/async-state-machine.md) → [сетевой I/O](../topics/dotnet/units/async-socket-pipeline.md) → [аллокации](../topics/dotnet/units/async-memory-and-allocations.md) → [production-диагностика](../topics/dotnet/units/async-production-capstone.md).

На каждом шаге формулируй ответ до раскрытия критериев. Выполняй связанные [лаборатории](../labs/dotnet/async-internals/README.md) и фиксируй **версию .NET, CPU, OS, ограничение подключений и наблюдаемые значения**. Не называй результат измерения языковой гарантией.

## Ошибки → интервальное повторение

Оценка «Пока не могу» или «Частично» создаёт отдельную карточку для этого конкретного пробела. Повторение не копирует основную теорию, а ссылается на соответствующий раздел. Существующие учебные вопросы активируются после изучения их раздела.

Пока ответы, самооценки и расписание хранятся в localStorage браузера; данные не отправляются в публичный GitHub. Наставник/интервьюер может отдельно проверить точность решения, потому что автоматической семантической оценки текстовых объяснений здесь нет.

## Оценка качества ответа

Хорошее объяснение должно содержать точные термины, порядок событий и отличать **гарантированное контрактом** от **детали реализации** и **измерения**. Для нагрузки — назвать ресурсы, лимиты, признаки деградации и способ подтвердить гипотезу.

Краткость полезна для собеседования, но глубокое понимание должно выдерживать дополнительные вопросы.
