# Стандарт технической точности

[Русский](technical-accuracy.md) · [English](technical-accuracy.en.md)

[Главная](../README.md) · [Каталог тем](../topics/dotnet/README.md)

Основная теория каждого механизма хранится **только в одной теме**. Вопросы и лаборатории содержат ссылки на неё и помогают закрепить материал, не дублируя объяснения.

## Для каждого утверждения фиксируем

1. **Контракт языка / API:** что гарантирует спецификация C# или контракт .NET.
2. **Реализация:** что делает конкретная версия Roslyn, CLR, JIT или библиотеки.
3. **Ресурсы:** CPU, heap, OS thread, стек, очередь, таймер, сетевое соединение — отдельно.
4. **Состояния конкуренции:** deadlock, гонки, contention, starvation и их условия.
5. **Наблюдаемость:** инструменты диагностики, измеряемые значения, ограничения эксперимента.

Никогда не заменяем конкретные механизмы фразами вроде «много памяти», «быстрее», «создаёт поток». Точное число аллокаций, длительность и количество worker-потоков не выдумываем: их нужно измерять в заданных условиях.

## Проверяемость

Исходные C#-файлы находятся в [labs/](../labs/README.md). Для недетерминированных сценариев проверяем допустимые свойства, а не единичный вывод. В учебном интерфейсе проверка предсказанного вывода явно отделена от реального запуска программы.
